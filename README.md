# GithubStarManager

简体中文 | [English](README.en.md) 

把 GitHub 的 Stars 页面从一条长列表变成可搜索、可筛选、可打标签的卡片网格。

脚本以用户脚本（Tampermonkey / Violentmonkey）的形式运行在 GitHub 页面里，只为桌面视口设计；窄于 768px 的视口下完全惰性，保持 GitHub 原样。

---

## 功能

### 卡片网格

- 把列表视图转换为卡片网格，并收窄左侧资料栏，把空间让给仓库。
- 响应式三栏：≥1200px 为「资料栏 180px + 卡片网格 + Starred Topics」；768–1199px 只保留网格。
- 本地分页，每页 30 条，与 GitHub 原生分页器同步；标题行右侧还会挂一份快捷翻页器（克隆原生分页控件，滚动到一半不用先滑到底）。
- 分页器中间的 `N / M` 可点击，原位变成输入框直接跳页（回车提交、Esc 取消、非法或越界静默忽略）。

### 搜索、筛选与排序（全部本地完成）

- 搜索：直接使用页面上的搜索框，匹配**作者 / 仓库名 / 描述 / 标签 / 备注**；命中词会高亮。语言不参与文本匹配（否则 `ASC` 会命中 `JavaScript`），要按语言请用语言筛选。
- 筛选：标签、语言（多选）、类型（Public / Private / Sources / Forks / Mirrors / Templates，多选）。筛选项按当前结果动态收窄。
- 排序：Recently starred / Recently active / Most stars / Most Forks，可切换升降序。
- 筛选条件走 URL 参数，刷新或分享链接后仍能复现；`Clear filter` 一键清空（保留排序）。

### 标签与备注

- 为任意仓库添加自定义标签（可多个）与备注。
- 标签、备注**按 GitHub 登录账号隔离**，换账号不会读到别人的数据。
- 点击标签即可把它加入筛选；筛选栏的 Tags 菜单只列出当前结果里出现过的标签。

### 同步

- 配好 Token 后做一次全量同步，把 Stars 成员关系、star 时间和仓库元数据写入本地缓存；此后的渲染、分页、筛选、搜索全部本地完成，不再请求网络。
- 同步入口两处，等价：TM 菜单「🔄 立即全量同步（GitHub API）」与标题行 Sync 按钮。任一入口触发，状态都显示在同一个按钮上（图标旋转 = 进行中）。
- 进页会自动做一次条件快筛：全部命中 304 就零额度早退，发现变化才拉整表。
- 检出变化后立即重渲染并弹出变更简报（只记「取消 star / 新增 / 恢复」三类计数，纯元数据刷新只进控制台），列表与简报永远一致。
- **完整性红线**：分页中断、解析失败、超过页数上限、速率余量不足时，整表放弃、不改动任何数据；半张表会把没拉到的仓库全部误判成「已取消 star」。

### 星标增删与恢复

- 卡片上的星按钮可直接加星 / 取消星，无需离开页面。
- 所有写请求串行执行、间隔不低于 1 秒（遵循 GitHub 官方 best practices，不并发、不自动重试）。
- 取消 star 后，标签与备注**保留 24 小时**（宽限期），期间可从 TM 菜单「♻️ 恢复已取消的 star（24h 内）」勾选恢复；恢复会真的调用远端接口，不只是本地回滚。
- 排队期间再次点击按钮 = 撤销这次操作（请求不会发出）。

### 导入 / 导出

- TM 菜单「📤 导出数据（标签/备注）」导出单个 JSON：只包含**有标签或有备注**的仓库数据。
- 「📥 导入数据（标签/备注）」在大窗里点击选择文件或直接拖入 JSON。
- 合并语义：标签取并集，备注以导入文件为准但空备注不覆盖本地非空备注，仓库元数据只补空缺。
- 导出包**不含 Token**、不含同步元数据（ETag 基线）、不含宽限期备份；包内带用户 ID，只能导入到同一账号。
- 导入后**不会**自动同步 —— 数据落盘即完成，是否拉远端由你自己决定。

### 他人的 Stars 页面

- 在别人的 Stars 页面同样能看到卡片网格，但数据**只来自当前页面已经渲染出来的条目**，不会为此发出任何网络请求（也不会写任何存储）。
- 他人的页面上：翻页用 GitHub 原生分页器；标签与备注按你自己的账号读取 —— 你已 star 的仓库可以就地编辑，其余只读展示（若该仓库正处于你的 24 小时宽限期备份里，标签与备注仍会显示，只是不可编辑）。
- 卡片上的星按钮状态永远只认你自己的缓存，不会把「对方收藏了」当成「我收藏了」。

### 其他

- 窄视口（<768px）完全惰性：不注入样式、不建节点、不改页面、不弹 UI、不发自动同步，也不拦截原生交互；窗口拉宽后自动恢复。
- 视口跨界实时双向切换，不需要刷新页面。
- 支持 Turbo 站内导航，往返于自己与他人的 Stars 页面不会串数据。
- TM 菜单「🙈 隐藏 Lists 区块」可隐藏个人主页的 Lists 区域（默认隐藏）。
- Token 归属校验：当 Token 所属账号与浏览器当前登录账号不一致时会常驻一条警告横幅（只告警、不阻断），避免读写方向相反。

## 安装

### 前置条件

先安装一个用户脚本管理器：

- [Tampermonkey](https://www.tampermonkey.net/)（推荐，Chrome / Edge / Firefox / Safari）
- [Violentmonkey](https://violentmonkey.github.io/)

### 安装脚本

从[项目 Releases](https://github.com/YsLtr/GithubStarManager/releases) 下载 `github-star-manager.user.js`，或在管理器里新建脚本后粘贴内容。

### 配置 Token

1. 打开 GitHub 的 Stars 页面（`https://github.com/<你的用户名>?tab=stars`）。
2. 在用户脚本管理器菜单里点「⭐ 设置 GitHub Token」。
3. 按配置面板提示创建 Token 并粘贴保存 —— 保存后会自动开始一次全量同步。

面板里还提供两条预填好权限的创建深链：

| 类型 | 能力 |
|---|---|
| **classic（推荐）** | 读写都可以，能对不属于你的公开仓库加星 / 取消星。建议 scope 取 `repo`。 |
| **fine-grained** | 读没问题；对不属于你、也不属于你所属组织的公开仓库没有写权限，此时写操作会改走浏览器登录会话。 |

Token 只保存在本地用户脚本存储中，不会上传到任何地方（导出包里也不包含它）。

## 使用

| 想做的事 | 怎么做 |
|---|---|
| 全量同步 | 标题行 Sync 按钮，或 TM 菜单「🔄 立即全量同步（GitHub API）」 |
| 搜索 | 页面上的搜索框，输入作者 / 仓库名 / 描述 / 标签 / 备注关键词 |
| 按标签筛选 | 点卡片上的标签，或用筛选栏的 Tags 菜单 |
| 按语言 / 类型筛选 | 筛选栏的 Language / Type 菜单（多选） |
| 排序 | 筛选栏的 Sort 菜单，可切换升降序 |
| 跳页 | 分页器中间的 `N / M`，或标题行右侧的快捷翻页器 |
| 加星 / 取消星 | 卡片上的星按钮 |
| 恢复 24 小时内取消的 star | TM 菜单「♻️ 恢复已取消的 star（24h 内）」 |
| 备份标签与备注 | TM 菜单「📤 导出数据（标签/备注）」 |
| 恢复备份 | TM 菜单「📥 导入数据（标签/备注）」 |
| 隐藏个人主页的 Lists 区块 | TM 菜单「🙈 隐藏 Lists 区块（开/关）」 |

> 完整网格依赖 Stars 缓存。没有缓存时脚本会显示配置引导，而不是半成品网格。

## 常见问题

### 为什么手机或窄窗口里看不到网格？

脚本只在视口宽度达到 768px 时启用；窄视口会保持 GitHub 原生页面，不做任何转换（也不注入样式、不建节点、不弹通知）。把窗口拉宽就会自动恢复，不需要刷新。

### 他人的 Stars 页面为什么只显示当前页？

他人页面的网格只使用 GitHub 当前已经加载的条目，不会自动拉取其余页面 —— 这是刻意的，为了不在别人的页面上消耗你的 API 额度。翻页请使用 GitHub 原生分页控件。

### 标签和备注会同步到 GitHub 吗？

不会。标签和备注保存在本地用户脚本存储中，并按当前登录的 GitHub 账号隔离；需要迁移时可使用导出与导入功能。远端权威的只有星标成员关系、star 时间和仓库元数据；标签 / 备注永远是本地权威，同步绝不会覆盖它们。

### 取消 star 之后我的标签还在吗？

在。取消后会保留 24 小时，期间从 TM 菜单「♻️ 恢复已取消的 star（24h 内）」可以恢复，标签与备注完好。超过 24 小时才真正丢弃。

### 为什么显示「Token 归属不符」？

因为 Token 所属账号和你浏览器当前登录的账号不是同一个。这本身可能是你有意为之（例如个人号读、工作号写），所以脚本只提示、不阻断。如果你确实想统一，打开面板重新配置 Token 即可。

### 为什么不使用 AI 批量总结项目内容？

AI 总结的内容不一定符合用户自己想要的备注，没有经过用户自己思考的备注基本上无效。用户需要自己知道自己为什么 star 这个项目。

### 为什么不做成浏览器插件而是做成油猴脚本？

脚本可以跟随油猴插件一起备份或迁移，浏览器插件需要依赖浏览器本身的同步功能或插件内自己配置同步，比较麻烦且不同浏览器之间的同步难以进行。

### 为什么不使用 GitHub Star 自带的 Lists ？

Lists 有最多32条以及 Lists 名称最多 32 个字符的限制，比较鸡肋，故不使用。脚本默认隐藏 Lists 部分，用户可以自行取消隐藏并正常使用 Lists 功能。

### 数据存在哪里？

只存在用户脚本管理器里，键名以 `stars_` 开头，主要是：仓库元数据缓存、每个账号一份的标签与备注、24 小时宽限期备份、同步元数据（ETag 基线与 Token 归属指纹）、Token 本身。Token 被排除在 localStorage 兜底镜像之外（`gm.ts` 的敏感键清单），导出包同样不包含它。脚本没有自己的服务器，除 GitHub 接口外不发任何请求。

### fine-grained Token 为什么加不了星？

GitHub 目前不允许 fine-grained Token 对「不属于你、也不属于你所属组织」的公开仓库写星标。脚本检测到 `github_pat_` 前缀时不会拒绝配置，而是改用浏览器登录会话完成写操作（读路径不受影响）。详见 [docs/adr/0004](docs/adr/0004-write-requires-classic-pat.md) 与 [docs/adr/0006](docs/adr/0006-web-endpoint-write-fallback.md)。

## 开发

```bash
pnpm install
pnpm dev       # 本地开发服务器（改动走 HMR）
pnpm check     # 类型检查 + 构建
pnpm build     # 产出 dist/github-star-manager.user.js
```

技术栈：Vite 8 + [vite-plugin-monkey](https://github.com/lisonge/vite-plugin-monkey) 8 + TypeScript（strict），产物是单个无运行时依赖的 `.user.js`。

开发环境配置（HMR 在 github.com 上的 CSP / Local Network Access 前置条件、`@grant` 只用 5 项的约束）与架构说明见 [DEVELOPER.md](DEVELOPER.md)；领域术语见 [CONTEXT.md](CONTEXT.md)；架构决策见 [docs/adr/](docs/adr/)。
