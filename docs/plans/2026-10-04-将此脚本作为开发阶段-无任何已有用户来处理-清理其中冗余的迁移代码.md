## 1. 目标与判定边界

### 1.1 要回答的问题

「把脚本当作开发阶段（无已有用户），其中冗余的迁移代码有哪些可以清理？」

### 1.2 in-scope：什么算「迁移代码」

**唯一判据**：其**唯一存在理由**是「本脚本**更早的构建**可能已在磁盘上留下旧形态数据」。含三族：

| 族 | 形态 | 本仓实例 |
|---|---|---|
| ① 键形态迁移 | 旧键 → 命名空间键，一次性搬运 | `legacyTags` / `migrateTagsIfNeeded()` |
| ② 存量记录清洗 + 代次阀门 | 读取时剔死字段；代次不符则强制整表换血 | `DEAD_REPO_FIELDS` / `isPlausibleLangName` / `DATA_REV` / `typeFlagsComplete` |
| ③ 外部命名空间的残留清除 | 旧构建曾写进「不该写的地方」 | `src/gm.ts` 里清除 PAT 的 localStorage 镜像残留 |

### 1.3 out-of-scope：看着像、实际不是（一律进 §8 拒绝清单）

| 排除项 | 为什么不是迁移代码 | 证据 |
|---|---|---|
| GM 缺席 ↔ GM 可用的 `localStorage → GM` 回写 | 服务的是**环境转移**，且该环境失败模式在本项目**会反复发生** | `src/gm.ts:9-11`；AGENTS.md「dev 模式必须知道的四件事」第 4 条 |
| GitHub 页面**代际**兼容（旧代 / 新代 / `/stars/{login}` 三套骨架并存） | GitHub **同时**服务多代骨架 = 活的兼容需求 | AGENTS.md D26 / 风险 17⑧；`src/domRepos.ts:16` |
| 本页会话的 DOM 回滚（`viewTeardown`） | 回滚的是**本次会话自己注入**的东西 | AGENTS.md D20 |
| 活功能：24h 宽限期 / 恢复菜单 / 语言色缓存 / 归属指纹缓存 | 是功能与缓存，不是迁移 | `src/storage/pendingDelete.ts:82-110` |

### 2.2 `isPlausibleLangName` 不只是死码，它有确认的假阳

```
src/storage/repoCache.ts:21  function isPlausibleLangName(lang: string): boolean {
src/storage/repoCache.ts:22    return /^[A-Za-z0-9+#'.\-_ ]{1,40}$/.test(lang);
```

字符类**不含 `*`**。而 linguist 的顶层语言名里有两个含 `*`：

- `F*`（官方条目：`F*: / fs_name: Fstar / color: "#572e30"` —— `fs_name` 这个字段正是因为 `*` 不是合法文件名而存在）
- `Pro*C`

⇒ 每次 `loadRepoCache()` 都会把这两个**合法**语言的 `lang` **静默删掉**（连带着那枚颜色也丢了）。换句话说：这块「清洗」不是「防御旧脏值」，而是「读取时误删当前合法数据」。删除它是一处**净修复**。

### 2.3 两个升级阀门已不可达（可达性证明，比「无用户」前提更强）

```ts
// src/fullSync.ts:70
const FULL_SYNC_TTL_MS = 48 * 60 * 60 * 1000;
// src/fullSync.ts:444-446
const baselineOk = !!meta.lastFullSyncAt && Date.now() - meta.lastFullSyncAt <= FULL_SYNC_TTL_MS && …
```

- 任何**超过 48h** 的缓存，`baselineOk` 本就为假 ⇒ 走无条件整表 ⇒ 语义与 Type 标志**一起**被换血。阀门不必参与。
- **48h 内**的缓存要带 `≤4.7.x` 语义，前提是「48h 内跑过 4.7.x 构建」；而 dev loader 的 `mountGmApi` key 由脚本头注释算出，**任何头字段变化（`@version` 最常触发）都必须重装 loader**（AGENTS.md dev 四件事第 4 条）⇒ 实际不可复现。
- 顺带：新鲜安装时 `meta.dataRev` 为 `undefined` ⇒ 阀门会打出「缓存代次旧（updatedAt 语义=updated_at，升级回补）」这条**不成立**的日志。删除即消掉一处误导输出。

⇒ 该结论**不依赖**「无已有用户」这一前提，对将来的用户同样成立。
