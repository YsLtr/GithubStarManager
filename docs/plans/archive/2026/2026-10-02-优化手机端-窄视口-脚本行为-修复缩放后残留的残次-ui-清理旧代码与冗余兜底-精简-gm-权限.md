## 4. 设计

### 4.1 断点单一真相

`isDesktop()` 改为 `window.matchMedia('(min-width: 768px)').matches`，媒体查询文本由 `constants.MOBILE_BREAKPOINT` 拼出（CSS 仍然写死 768，因为 CSS 读不到 TS 常量 —— 这一点在 `base.css` 顶部注释里写明「与 `constants.MOBILE_BREAKPOINT` 必须同步改」）。

理由不是「更现代」，而是**构造性一致**：只要 JS 与 CSS 用同一个媒体查询，就不可能出现「JS 认为桌面、CSS 认为手机」的错位窗口；`innerWidth` 与媒体查询在 Safari 上口径不同（P9）。`matchMedia` 在 `document-start` 阶段已可用（实测）。

### 4.2 生命周期层（`src/lifecycle.ts`）

新增最小模块，解决 P8：

- `track.addListener(target, type, handler, opts)`、`track.timeout(fn, ms)`、`track.raf(fn)`：登记即受管，返回可单独取消的句柄；`disposeScope(scope)` 统一 `removeEventListener` / `clearTimeout` / `cancelAnimationFrame`。
- **世代号 `generation`**：`transformStarsView()` 与 `teardownStarsView()` 各递增一次；所有异步回调（重试链、`turbo:*` 的 100/200ms 延迟、`scheduleProbeSync` 的 2s、`search` 的 50ms）在真正动手前比对世代号，过期即静默丢弃。
  - 依据同 `src/mutationQueue.ts` 中「`.then` 里必须做 handle 身份校验」的既有教训（AGENTS.md 决策 D10）——没有世代号，teardown 会被自己排队的回调撤销。
- 只做这两件事，不引入通用框架；通知栈的 3 个全局位置监听（`notifications.ts:178-182`）也登记进来。

### 4.5 双向切换接线

```
matchMedia('(min-width:768px)') change (± 150ms debounce)
  ├─ 变窄:  如果当前是「已转换」态 → teardownStarsView('跨断点收窄')
  └─ 变宽:  如果在 Stars 页 → transformAndReveal(false)（复用手动同步后的既有路径）
```

`transformStarsView()` 与 `teardownStarsView()` 用 `state.view: 'idle' | 'active'` 做门，保证幂等：重复 teardown 无副作用，重复 transform 命中 `.stars-grid-container` 早退。

### 4.6 GM 权限精简的实现细节

- `gmFetchText` 从 gm.ts 删除，语言色改用 `fetch(url, { cache: 'no-cache', signal })` + 手动 `AbortController` + `setTimeout(20000)` 清理（**不能用** `AbortSignal.timeout`：`vite.config.ts` 的 `cssTarget` 含 `safari15`，同一轮兼容性口径下不用 16+ API）。保留现有单飞、30s 失败冷却、解析为空 fail-closed。
- `hideListsMenu` 改为只走 `GM_registerMenuCommand(name, fn, { id })`；保留「拿不到 id 时仍能注册成功」的判断，但不再有 `GM_unregisterMenuCommand` 分支。
- `vite.config.ts` 的 `@grant` 删 3 项后须逐项回归：菜单（`GM_registerMenuCommand`）、存储（`GM_getValue`/`GM_setValue`）、Token 深链（`GM_openInTab`）、导出（`GM_download`）。
- `gm.ts` 里 `GM_addStyle` 的注释残留一并删（从未 `declare`、从未 `grant`，样式走原生 DOM）。
