# 他人 star 页零网络只读网格

> **目标**：在别人的 star 页（`{login}?tab=stars` 与 `/stars/{login}`），把**页面上已经渲染好的原生条目**
> 投影成脚本自己的卡片网格并**只读**渲染，显示**我自己已有的**标签/备注。
> **硬约束（用户口径）**：只获取页面中已有的数据，**不拉取**；一次网络请求都不发；不落盘任何数据。
> 分页与筛选**委派 GitHub 原生控件**。

## 1. 数据来源与边界（核心约束）

| 项 | 结论 |
|---|---|
| 网络请求 | **0 次**（他人页路径全程）。不调用同步、不做归属校验请求、不发语言色请求 |
| 数据来源 | 页面已渲染的原生条目：`div.col-12…tmp-py-4.border-bottom`（profile 标签页）/ `ul.repo-list > li`（`/stars/{login}`） |
| 条目标识 | 条目内 `user-list-menu[data-repository-id]` —— 它就是标签/备注的存储键，**无需**解析仓库名 |
| 星状态 | `div.starring-container` 是否有 `on` 类（服务端渲染，精确表达「**登录者**是否已 star」；真机实测 127 条目零假阳零假阴） |
| 持久化 | **无**：一次「页面 → 内存表」的投影，随导航丢弃；**不写任何存储键** |
| 字段缺失 | **留空不猜、不补请求**；缺失清单由 T1 真机逐条比对后回填到本节 |
| 分页 | **原生分页器**（自带 `after`/`before` 游标）；脚本不下分页器、不下跳页输入 |
| 筛选 | **原生筛选栏**（Type/Language/Sort）；脚本不挂筛选栏、不拦截原生搜索 |
| 只读 | 卡片无星标按钮；标签/备注只读渲染（无 × / + / textarea，点击无反应，`cursor: default`，一个 `title`） |

**为什么分页必须委派原生**：真机实测 HTML stars 页的 `?page=N` **被忽略**（返回第 1 页内容），真实翻页是
`after`/`before` 游标；而脚本的本地分页器/跳页（D22）建立在「整表在手」之上 —— 只有当前页数据时，
挂本地分页器等于给出无法兑现的页码。

## 2. 方案

### 2.1 分层

```
入口分派 (index.ts)             ← 他人 star 列表页 + 桌面视口 + 已登录
  └ 投影  src/domRepos.ts       ← 新：纯函数，DOM 条目 → RepoData[]（缺字段留空）
  └ 来源  src/viewContext.ts    ← 新：mode/readOnly/pageRepos(仅内存)/ownerLogin
      └ 渲染 filters.ts（复用）           ← queryRepos 按来源取表；renderBrowsePage 带只读开关
          ├ 卡片 ui/cards.ts（复用，不改）         ← 纯 DOM、零监听，本就会建空的标签/备注容器
          └ 只读标签/备注 readonly.ts（转 export）  ← 复用 4.12.0 的 builder 与 .gsm-ro-* 样式
  └ 接管 transform.ts           ← 改：宿主适配两条路线；**只藏原生条目**，原生分页器/筛选栏/Lists 不动
  └ 回滚 viewTeardown.ts        ← 改：登记网格与说明行；原生条目走既有 GSM_HIDDEN_ATTR 项
```

### 2.2 流程

1. **判归属**：`isStarsListingPage()` 且 `getStarsPageScope() !== 'own'` 且**已登录**（能取到 `octolytics-actor-id` / `user-login`）。
2. **投影**：`collectPageRepos()` 从原生条目提取 `RepoData`（两条路线；认不出 ⇒ 放弃接管）。
3. **接管**：`hideNativeNode()` 隐藏**仅原生条目**（打 `GSM_HIDDEN_ATTR`）；插入网格 + 说明行；`N === 0` 走空态文案。
4. **渲染**：`renderBrowsePage` 只读上下文 —— 无星按钮、标签/备注只读、不挂分页器。
5. **翻页**：用户点**原生分页器** → GitHub 自带游标导航 → 重新投影（零请求，页面内容即数据源）。

### 2.3 红线

- 他人页**零网络**（唯一允许的副作用：读本地存储、注入样式表）。
- **零存储写入**；不碰 `stars_repo_cache` / `stars_full_sync_meta`；标签/备注仍用**我自己的**命名空间（D27）。
- 不改 `cards.ts`；不新增 `@grant`（仍 5 项）；不引新依赖；零写路径。
- 只隐藏原生**条目**（经 `hideNativeNode`）；原生分页器/筛选栏/Lists 一律不动。
- 窄视口完全惰性；回滚按痕迹；不碰其它 GitHub-owned 节点属性。

## 6. 验收标准（可执行）

1. 两条路由桌面视口出现卡片网格，内容 = **本页原生条目**的投影（条目数与仓库名一致）。
2. **他人页 fetch 计数 = 0 且 `GM_setValue` 计数 = 0**（整个生命周期：进入、渲染、翻页、点击）。
3. 网格内 `.stars-star-btn` = 0、`input`/`textarea` = 0；点击标签/备注后 DOM 不变、无对话框。
4. **原生分页器与原生筛选栏仍在**，且其 `display` 未被改动（无 `data-gsm-hidden` 落在其上）；点原生分页器能翻页，翻页后网格随之更新。
5. 我已有的标签/备注出现在对应卡片上（用**我的**命名空间）；本页无命中则无徽章（正常）。
6. 说明行含「本页 N 个」与「只读」；`N === 0` 显示空态文案。
7. 宿主认不出 ⇒ 不接管：原生列表原样、无脚本痕迹、无报错、无文案。
8. 窄视口（<768px）：`gsm-*` / `stars-*` 节点 0、无 `display` 改动、零网络。
9. 他人页 → 自己的页往返：条目 `display` 全还原、`data-gsm-hidden` 全清、`viewContext` 复位，
   **自己的页显示自己的数据**，其同步/简报/分页/语言色零回归。
10. `pnpm check` 绿、`node scripts/verify-css.cjs` EXIT 0、`pnpm test:exportimport` 51/0、dist `@grant` 恰 5 项。

## 7. 回滚与风险

- **回滚**：只新增「投影 + 内存来源 + 只读开关 + 宿主适配」四处，全部登记进 `viewTeardown`；
  复位 `viewContext` 即退回「他人页零痕迹、自己的页照常」。**不触碰同步引擎**（本方案最大优势）。
- **风险 1 · DOM 字段缺失（最大不确定性）**：原生条目未必含卡片所需的全部字段。缓解：T1 真机逐条比对，
  缺什么就不渲染什么；`buildCardFromCache` 本身不假设字段齐全。
- **风险 2 · 两条路由结构差异**：`/stars/{login}` 与 profile 标签页不同构；宿主抽象认不出即静默放弃，
  不留残次网格。
- **风险 3 · 卡片上的标签/备注只在「我也 star/标记过该仓库」时出现**：mattn 页与本人在 21 个标签仓库交集为 0
  ⇒ 网格看起来「没有任何标签」属**预期**，不是缺陷。编辑入口仍只在**我自己的** stars 页
  （与他人页零写入口的裁定一致）。
- **风险 4 · 原生控件被误伤**：若日后有人把「隐藏原生条目」写成隐藏整个容器，会连带藏掉分页器/筛选栏
  ⇒ 验收标准 4 专门断言。
- **明确不做**：`/users/{u}/starred` 拉取（含预取/缓存/条件请求）、他人数据落盘、脚本分页器与跳页、
  脚本筛选栏、`/stars`（无登录名段的本人新版页）、对方的私有可见 star。
