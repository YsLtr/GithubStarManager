## 1. 目标与判据

### 1.1 要回答的问题

「符合 ponytail 的教训，这个项目还可以如何优化精简？」——ponytail 的教训不是「把代码写短」，而是：

1. 先问 **这东西是否本该存在**（YAGNI）；
2. **已有实现就复用**，不要在多处各写一份；
3. 删除优先于新增，文件越少越好；
4. **绝不**简化掉信任边界的校验、防数据丢失的错误处理、安全与无障碍；
5. 有意为之的简化要留下记号与升级路径。

### 1.2 度量口径（D2）

| 指标 | 用途 |
|---|---|
| `src/**` 维护面行数净减少 | 主指标。当前基线：TS 8836 行 + CSS 892 行 |
| 「同一概念实现了几处」的处数减少 | 主指标。**处数每减 1 = 消除一个漂移点**（本项目自认的最高价值缺陷模式） |
| ~~dist 产物体积~~ | **不用**。产物 189.1K / 4894 行，装一次由 TM 本地缓存，压体积对用户零收益；以它为标的只会诱导压缩注释 |

### 1.3 不变量（D3）

**零用户可见行为变化。** 所有条目只允许「删除 / 去重 / 抽一行 helper」。硬约束：

- `pnpm check` 绿（`tsc --noEmit` + `build`）
- 动到 `RepoData` 字段或 `storage/exportImport.ts` 判空逻辑 ⇒ 加跑 `pnpm test:exportimport`（51 项必须 0 失败）
- 动到渲染分派 / 星按钮 / 卡片 ⇒ 必须 `node .diag/gen-otherstars-harness.cjs` 重新生成夹具（夹具内联 dist，**不跟随 build**）并跑既有场景，`__errors` 全空
- 只动 CSS ⇒ 加跑 `node scripts/verify-css.cjs`，EXIT 0
- 发布前核 dist 头部 `@grant` 恰 5 项

### 1.4 排序原则（D4）

`A 删除 → B 单一真相收敛 → C 文档瘦身 → D 有意不做`，同级内按「删除行数 ÷ 回归风险」降序。**一件一提交**，逐项独立回滚。

### A4 — `RepoData` 的 `ts` 字段（缓存写入时间戳）只写不读

> **先澄清命名**：这里说的是 `RepoData` 接口上的**一个字段 `ts`**，**不是**一个叫 `RepoData.ts` 的文件（原稿这样写容易误读，已改）。它是一个 13 位毫秒时间戳，语义 =「这条仓库缓存是什么时候写进来的」，与 `starredAt`（star 时间）、`updatedAt`（最后 push 时间）都不同。

**它当年是干什么的（git 实证）**：`ts` 随 3.0.9「外部 unstar 检测（到货快照 diff）」引入（`git show dceeef5:src/types.ts` 里的注释即为「缓存写入时间」）。那一代机制把「刚到达的页面快照」与缓存比对，需要逐条目判断**哪几条是新到货的**，`ts` 就是那个判据的原料；同一时期还有配套的 `StarVerdict`（裁决时间戳）与 `shiftPending`（位移挂起时间戳）。

**它为什么现在可以删**：那整套机制已在 **4.0.10 被整簇拆除** —— commit `eef4f3e` 的提交信息原文：「死码簇拆除(snapshot/裁决缓存/shiftPending, 历史键一次性清理)」，同一提交删掉了 `src/snapshot.ts`（36 行）、`StarVerdict` 类型与两个历史存储键。星状态真相自此改由**整表 diff** 权威判定（现 D6；「到货快照 / 位移挂起 / 双 404 核对」在 AGENTS.md 里已标为**作废决策 D1 / D2 / D4**）。读取点随那一簇一起消失，**唯独写入点被落下** ⇒ 只剩 `repoCache.ts:61` 一处白写。

**判据复核（我逐点核过）**：不是「看名字像没用」，而是三类证据同时成立 —— ① 全提取消费者（`entry.ts` / `.ts ` / 解构 / 模板串四种形态全试过，零命中）；② 引入它的机制的**载体已被删除**（4.0.10 拆簇，有 commit 与 diff 为证）；③ 同族的 `updated` / `langColor` 早已被同样的理由纳入 `DEAD_REPO_FIELDS` 清洗（4.8.0 先例），`ts` 是那批遗漏的第三个。

**若将来要用**：`ts` 唯一的自然用途是「按条目陈旧度判断要不要刷新」（例如「缓存超过 N 天就强制重拉这个仓库」）。真要做时**一行就加得回来**（`Object.assign(..., { ts: Date.now() })` + 字段声明），且届时应同时写清消费方 —— 这正是删它的理由：**没有消费者的字段不是设计，是残留**（ponytail 阶梯第 1 级：这东西本该存在吗？）。

| 事实 | 证据 |
|---|---|
| 唯一声明 | `src/types.ts:23` `ts?: number;` |
| 唯一写入 | `src/storage/repoCache.ts:61` `Object.assign({}, all[repoId] || {}, data, { ts: Date.now() })` |
| 读取点 | **零**（逐点核对了 `entry.ts` / `.ts ` / 解构等所有形态） |
| 未纳入清洗 | `DEAD_REPO_FIELDS`（`src/storage/repoCache.ts:31`）只含 `['updated', 'langColor']` |

处置：去掉 `{ ts: Date.now() }` 写入与 `types.ts:23` 声明，把 `'ts'` 加进 `DEAD_REPO_FIELDS`（沿用 4.8.0 的存量自愈机制）。
**已知副作用**：导出走 `keptCache[repoId] = cache[repoId]`（`src/storage/exportImport.ts:75-83`）整条拷贝，故 `ts` 现在确实进导出包。删后导出条目少一个**未被任何读取点使用**的可选字段 ⇒ **不 bump `schemaVersion`**（见可变决策 V3）。

## 5. Tier D 的完整理由（拒绝清单）

**D5 不拆大文件。** `fullSync.ts` 999 行里是 6 个真实关注点（状态机 52–127 / HTTP 层 130–255 / 并发原语 257–289 / 完整性阀门 313–430 / 单遍扫描 432–567 / 差异应用与编排 571–816 / TM 菜单 820–879 / Sync 按钮与调度 882–996），`filters.ts` 963 行是 5 个（纯领域 43–231 / 分页渲染 233–320 / 高亮与信息条 322–419 / 状态编排 427–491 / URL 解析 493–579 / 菜单组件 590–962），`index.ts` 615 行是 4 个。**这些不是样板代码**，拆开只会把 1 个文件变成 4 个文件、增加导出面。ponytail：「Fewest files possible」。判据：**没有改动摩擦的证据** —— 近期改动都落在局部函数内。

**D6 不打破 6 成员 SCC。** 环内 `cardAreas / filters / ui/cards / restore / starCheck / ui/tagFilter`，10 条边**全部只在函数体内调用**，逐行扫描确认**零顶层可执行语句**（唯一模块级副作用在 `index.ts:599-605`）。已有先例（4.14.0 把 `hasApiData` 从 `fullSync.ts` 迁到 `storage/repoCache.ts`），但那是为了消除**真实**的 `cardState → fullSync → starCheck → cardAreas → cardState` 依赖并让 `cardState` 不依赖 fullSync（理由写在 `storage/repoCache.ts:7-13`），不是为了「消除环」本身。为一个无害的环动 6 个模块是投机性工作。

**D7 不合并两条 unstar 保全管线。** 表面重叠（移入待删除区 + 备份标签备注 + 清空活区 + 删缓存条目），实质不同：
- `markRepoUnstarred(repoId, seed?)`（`storage/pendingDelete.ts:83-118`）= **用户主动** unstar。备份创建是**条件式**（缓存有 / 给了 seed / 当下有非空标签备注），且 `seed` 专门为「他人 stars 页的内存投影条目」存在。判据 `if (!existing && !seed && tags.length === 0 && !note) return;` 是 4.14.0 从 `if (!cache[repoId]) return` 改来的 —— 旧判据在他人页会导致「不备份且不清空活区 ⇒ 标签永久留在存储里而只读卡片没有删除入口」。
- `confirmExternalUnstar`（`starCheck.ts:93-127`）= **远端权威确认**。无条件建备份 + **幂等自愈**（已在宽限区仍要清缓存回写脏态，否则每轮同步恒报同一个外部取关，实例 `zai-org/ZCode`）。

合并会抹掉其中一条防护的语义。ponytail 原文：「**Never** simplify away … error handling that prevents data loss」；并且「the smallest change in the wrong place isn't lazy, it's a second bug」。

**D8 不合并两个只读判据。** `isReadOnlyScope()`（`index.ts:81`）= `isStarsListingPage() && getStarsPageScope() !== 'own'`，**纯 URL/DOM 派生、无状态**，决定入口分流（是否接管、是否挂同步按钮）；`isReadOnlyView()`（`viewContext.ts:79`）= `otherPage !== null`，**模块态**，决定渲染分派与 `applyFilters` 门。二者构成两阶段不变量（入口决定接管 → 接管成功投影才存在）。4.14.0 修的缺陷来自混淆「**视图级**判据 vs **逐卡片**判据」（D29），与这两个判据的分工无关。

**D9 不批量删注释。** TS 注释约 2486/8836 ≈ 28%，但 `src/lifecycle.ts:1-14`、`src/dom.ts:6-8`、`src/storage/repoCache.ts:7-13`、`src/styles/persistent.css:15-27` 这类注释承载的是**实测与官方依据**，无法从代码恢复。只删 A6 那三处指向已删函数的悬空注释。**明确不设百分比目标**。

**D10 不为手工测试工装造运行器。** 关键事实：`tests/smoke/fixture.html` 是**活输入** —— 被 5 个 `.diag/gen-*.cjs`（account / jump / otherstars ×2 / readonly / viewport）`readFileSync` 消费，删了会连锁破坏夹具生成。`tests/smoke/assert-*.js`（3 个 / 157 行）与 `tests/diag/selectors.js`（78 行）是 `agent-browser-cli exec --file` 手工注入用的，本就没有也不需要运行器。`package.json` 只有 5 个脚本，无测试运行器。为 235 行手工工装建 CI 是投机性工作；AGENTS.md 也明确「快速构建期不跑 smoke，改完只 `pnpm check`」。

**D11 不实现存储层读缓存。** AGENTS.md 已登记的 P2：「逐卡约 5 次 `GM_getValue`（30 条约 150+ 次同步 IPC）」。加「读缓存 + 写失效」会改动**全脚本共用**的新鲜度语义 ⇒ 与「精简」主题无关，独立立项。

**D12 不「统一」CSS 选择器的不对称。** `persistent.css` 的过渡规则**刻意不带** `gsm-stars-layout` 标记，而 base/wide 的**尺寸**规则必须带。理由（ADR 0009 追加 6，含夹具 A/B：认标记时退出后匹配 transition 的规则数 = 0、不认时为 1）：「撤尺寸规则与摘标记在 `exitStarsView` 的同一个同步任务里，过渡若认标记就没有 after-change 声明 ⇒ 回弹不启动、尺寸瞬跳」。**两个要求方向相反，别为「一致性」统一它们。**

**D13 不改归档文档里的历史口径。** 例如 D28 记录的「`?page=N` 对 HTML stars 页无效」等实测结论。归档文档是历史记录，`git log` 是权威；改写它们没有收益，还会破坏可追溯性。
