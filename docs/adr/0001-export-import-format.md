# 导出包格式与导入合并语义

导出包是**单个 JSON**，顶层 `{ kind, schemaVersion: 1, exportedAt, user: { id }, data: { tags, notes, repoCache } }`；**不含 `github_pat`**（敏感键，跨设备搬运 token 高危且无必要），**不含同步元数据**（ETag 基线），**不含宽限期备份**（临时状态，搬运即近乎立刻过期）。

`repoCache` 只带**有标签或有备注**的仓库——仓库元数据随时可由一次同步刷新，导出只需保证这些仓库在导入后立刻有完整卡片。

导入按 `kind` + `schemaVersion` 严格校验，不匹配则整包拒绝、不写任何键——沿用 DEVELOPER.md §6 的完整性红线精神。

合并语义：标签取并集（去重、本地已有在前）；备注以导入文件为准，**但空备注不得覆盖有内容的备注**——「空」的判据是 **trim 后为空**，`storage/notes.ts` 的 `saveNote` 判空同步收紧为同一判据（只输入空格/换行的备注视为删除）。

导出包带 `user.id`，只允许导入到同一用户 ID 下；当前页取不到 `user.id`（未登录 / GitHub 改版）时导出与导入**一律拒绝并提示**，不降级到无隔离的旧键——那会把数据写进一个「下次登录后读不到」的键，等于静默丢数据。

注意：`repoCache` 条目沿用「按 repoId 键」的结构，**不含命名空间**，因此 `user.id` 是导出包的自声明归属，不是数据隔离手段——身份校验必须在导入侧显式执行。

## Considered Options

- **导出仅标签/备注，不带仓库元数据**：被否决。在新设备导入后卡片缺仓库名/语言/star 数，等于必须再等一次全量同步才可用；代价只是一段 JSON，故为**有标签或有备注**的仓库带上 `repoCache`。
- **导出带同步元数据（ETag 基线 `etags` / `tailEtag`）**：被否决。ETag 基线与「当前 token 身份 + 远端瞬时状态」绑定，跨设备/跨时间导入会让「全 304 = 无变化」误判为「本地缓存即现值」，是数据正确性红线。
- **导出 `repoCache` 全部条目（含与当前 star 集合无关的脏条目）**：被否决。导出取最小集，脏条目对导入方无用。
- **允许跨账号导入**：被否决。repoId 是「我的 star 集合」的一部分，把别处数据挂到当前账号无法解释；`user.id` 不匹配即拒绝。
- **导入时弹「覆盖 / 合并」二选一**：被否决。多一套对话框与状态机；并集 + 备注单向覆盖已能表达用户的主动意图。
- **导入前自动导出一份当前状态**：被否决。会连续触发两次下载（浏览器可能拦截后一次），且无法保证用户真的保存了文件。
- **`GM_download` 之外再挂 Blob + `<a download>` 原生兜底**：被否决。TM 的扩展名白名单是**用户设定的安全边界**，原生下载能绕过它，等于让脚本替用户推翻自己的设置；而且 TM 因白名单/功能未开拒绝时**不抛错、只走 `onerror`**（TM 文档：`GM_download` 返回 `{ abort }`，只有 `GM.download` 才是 promise），同步 try/catch 根本捕获不到，所谓兜底在它唯一有意义的场景里是**死代码**。故只调 `GM_download`：不可用或同步抛错就返回失败并提示，白名单类失败由用户去 TM 设置解决。

## Consequences

导出的 JSON 与账户绑定，天然不可作为跨账号迁移工具；若将来确需迁移，得先把标签键改成不按用户隔离，那是另一个决策。

导入是破坏性操作（备注可能被覆盖）且**不做自动备份**：回退只能靠用户自己事先导出的文件，提示写在导入 `confirm()` 文案里。

## 交互与流程

导入的破坏性动作由**原生确认对话框**承载（`window.confirm`），校验失败用 `window.alert` 报原因且**不弹确认**——校验失败时不存在可执行的操作，同一种对话框会让用户以为「点确定就能强行导入」。与 `starCheck.ts` 的 `window.prompt` 同族；脚本只运行在 github.com（`@match https://github.com/*`），不引入页面内确认条。

导入完成后**直接调用同步函数**（与标题行 Sync 同一路径 `runFullSync('button')`）。无 Token 时给出错误提示并跳过同步——**不弹 Token 输入框**（导入是数据搬运，此刻的预期不是被要求配 Token）。同步失败同样以错误提示呈现，并**保留**既有 401/403 → Token 配置面板的通道（Token 失效必须可见，否则星星按钮会静默失效）。

导入**不触发导航**：TM 菜单在仓库详情页/纯 profile 页也能点，导入后数据已落盘，用户下次进 Stars 页自然会读到新数据；重新渲染只在「Stars 页且网格已存在」时执行。

文件名 `<script-slug>-<user.id>-<YYYY-MM-DD-HHmm>.json`（本地时区、分钟精度，不含 Windows 禁用字符）；包内 `exportedAt` 写 ISO 8601 UTC——文件名给人看，字段给程序看。`<script-slug>` 必须**单源**，脚本改名时文件名跟着变，但包内 `kind` 是协议身份、**永不随改名变动**。

导出时清洗：trim 后为空的备注**不写入导出包**，其余备注文本**原样保留不 trim**（避免吃掉用户在备注里有意写的前导空格）。`storage/notes.ts` 的 `saveNote` 判空同步收紧为「trim 后为空」，只影响写入——存量空白备注不做批量清洗（无渲染危害，不值得为显示瑕疵做全体用户写操作）。
