# 0013 · 编辑会话期间挂起重绘

- 状态：已采纳（4.20.0，2026-10-22；4.20.1 修正「blur 在摘除之前派发」那一条）
- 取代：`AGENTS.md` 旧 D12（「同步后**立即**重渲染，不问是否刷新」）与 D12 补；两条硬口径整条删除，合并为本条（D36）
- 相关：`0009`（他人页网格）、`0005`（导入后不自动同步）、`src/filters.ts`、`src/inlineEdit.ts`

## 背景

用户在卡片上编辑标签或备注时，任何一次网格重绘都会把编辑框连同卡片一起换掉：编辑态退出、刚打的字从屏上消失。报告的触发语是「刷新后重渲染页面」——最典型的一条正是**进页自动同步**：`transformAndReveal` 成功后 2s 发 `runFullSync('auto')`，只要任意可见元数据变化（`refreshed` 计入任一字段）就重绘整张网格，恰好落在「刚刷新完、正在改备注」的那几秒。

必须先把缺陷的机制记准，否则修法会跑偏（本轮实测把最初的两个判断都推翻了）：

1. **编辑态一定退出**。`renderBrowsePage` 是唯一拆建点，用分片 + `replaceChildren` 整批换卡（为了不出现空网格，见下），旧卡片上的输入框无处可留。
2. **草稿在屏上没了，但存储里可能已经有**。分片是在 `replaceChildren` **之前**按当时的存储值建好的；重绘其间发生的提交只写存储，而此后没有第二次渲染 ⇒ 新卡片停在旧值。夹具 A/B（关掉本决策的挂起门）实测：`stored: 'draft-y'`、`onCard: '添加备注…'` —— 数据落了盘，用户看到的却是「字没了」，要等下一次无关重绘才莫名冒出来。
3. **「重绘时先提交再重建」救不回来，也不能靠 blur 收尾**。Chromium 实测在移除聚焦元素时**会补发** `blur`（夹具 `premise_blurOnRemove=true`），所以提交本身能跑；但此时事件目标已在文档外，`blur` / `focusout` **传播不到 document**，任何挂在 document 上的收尾逻辑都收不到。本决策的第一版实现就死在这上面：挂起之后永远等不到「编辑结束」，网格一直停在旧画面（夹具当场抓到）。

## 决定

**卡片里有未提交的编辑会话时，不重绘，改挂起；编辑结束后再原样补跑一次。**

- 挂起的是 `applyFilters` **整条**（常驻控件原位刷新 + 网格 + 筛选信息条），不是只拦 `renderBrowsePage`：挂起期间不碰任何 DOM，因此不存在「控件刷新了、网格没换」这种半应用中间态。
- 判据只有一个：页面上存在 `.stars-card-notes-edit` / `.stars-tag-input`（`src/inlineEdit.ts` 的 `hasInlineEditor`）。这两个编辑器都是按需节点（点开才建、提交/取消即摘），**存在 ≡ 有未提交草稿**。刻意不用 `document.activeElement`：窗口失焦后节点与草稿都还在，焦点却已经不是它。
- 挂起槽只有一个（模块级单例），多次请求按规则并成一次：只要有一次要求「回第 1 页」（筛选条件变了）就以它为准，全部 `keepPage` 才保持当前页。至于「哪个画面是对的」——只有当前筛选条件 + 当前页这一份。
- 编辑结束的三个信号（缺一不可，全部由 `filters.ts` 持有，随挂起态一起装卸）：
  1. `blur`（document **捕获**相位）：点击别处、窗口失焦。必须是捕获相位 —— 提交处理器会就地摘掉编辑器，摘掉之后的 `focusout` 目标已在文档外、传播不到 document。
  2. `keyup`：Enter / Escape 提交是在 keydown 里摘节点，keyup 落到 body，靠它补。
  3. `pointerup` / 窗口 `blur`：指针没松开就不重绘（换掉 mousedown 目标会让 `click` 被改派到共同祖先 ⇒ 那一下点击静默失效），松手后再排一拍。
- 兑现排在 `setTimeout(0)`：提交处理器（`saveTags` / `saveNote` + 局部重画）与这次手势的 `click` 都要先走完。
- 撤除时机：`viewTeardown`（跨断点收窄 / 离开 Stars）与 `exitOtherStarsView` 都调 `cancelDeferredApply()` —— 迟到的重绘会往已还原的原生筛选行里插控件、或对着上一张视图渲染。
- 视图销毁路径**按失焦语义提交草稿**（`commitInlineEditors()`）：那条路直接把节点删掉，而删节点时派发的 blur **不能依赖**（不同引擎时机不同，且那一刻视图已在半拆状态、`renderNotes()` 会往游离容器里画）。主动提交一次是确定的，不押在引擎行为上。
- 单卡重绘（`syncCardAfterStarChange`）走同一判据：正在编辑的卡片不重画标签/备注区（星标外观照常改），有激活筛选时挂一次整表重绘。
- **唯一例外：外部取关**。此时卡片即将转只读，挂起不成立 —— 数据归属已移到 24h 宽限期备份，让编辑器继续开着等失焦提交，写进的是活区孤儿数据（只读渲染读备份，看不见它；re-star 时还会被备份值覆盖）。故先把草稿**并进备份**（`mergeDraftIntoGraceBackup`），再刷只读。
- 编辑器的提交加一条 `isConnected` 守卫：节点已离场就不落盘。它挡住的是「异步移除 / 卡片整体销毁」之后才到的 blur。
  **注意（4.20.1 修正）：这条挡不住「脚本重绘摘掉编辑器」** —— 见下面的追加。
- **4.20.1 追加：脚本自己发起的重绘，其间的 blur 一律不算提交（`suppressInlineCommit`）。**
  实测（夹具，三次一致）：Chromium 在把聚焦元素**摘出 DOM 之前**就派发 `blur` —— 派发那一刻
  `isConnected === true`、`parentNode` 还在、`document.contains()` 也 true。所以 D36 第一版把「节点已离场 ⇒ 不提交」
  当兜底是**不够的**：从可编辑翻成只读那次重绘里，编辑器会把这次 blur 当成用户提交，于是
  ① 草稿被写回**活区**（外部取关后活区该为空 ⇒ 孤儿数据）；② `commit` 里的 `renderNotes()` 把
  「点击进编辑」的监听**重新绑上** ⇒ 只读卡片又能点开编辑框、又能写字（用户报的正是这一条）。
  判据只能是「这次重绘是谁发起的」：`ui/notes.ts` / `ui/tagFilter.ts` / `readonly.ts` 清空容器时把自己包进
  `suppressInlineCommit()`，由此产生的 blur 不算提交。`commitInlineEditors()`（销毁路径）**不做**抑制 —— 那里要的就是提交。

## 被否掉的替代方案

| 方案 | 否决理由 |
|---|---|
| 重绘前强制 flush 提交 | 仍会退出编辑态；半截输入被当提交（「rea」变成真标签）；提交跑在拆节点时，写进的是旧容器/活区，屏上依旧是旧值（见背景第 2、3 条） |
| 快照 + 重绘后重开编辑器 | 要新建一套编辑会话登记表、重建焦点/选区/滚动、还要处理「卡片已离场/转只读」的降级；且 IME 组合期被销毁无法快照。收益只是「少退出一次编辑态」，成本与风险都远高于挂起 |
| keyed 增量渲染（按 repoId 复用卡片节点） | 根治且顺带解决滚动/焦点，但等于重写渲染层，且要重新证明 D12 的空网格约束 —— 留作长期方向，不在本轮 |
| 跨整页刷新持久化草稿（sessionStorage） | 挂起只保内存；F5 / Turbo 换帧仍需持久化。属另一个交互决定（「刷新后自动重开编辑器」），本轮只做挂起 |

## 后果

- **网格会短暂陈旧**：同步简报已经弹出、网格却还是旧画面，直到用户结束编辑。这是本决策明确接受的代价 —— 有 `console.log('卡片正在编辑：本次重绘推迟到编辑结束后（D36）')` 与兑现时的对应一行留痕，真机排查时能对上。
- 挂起期间到达的新请求按合并规则覆盖，不会排队堆积；用户结束后看到的永远是「当前条件下的正确画面」。
- 重绘从一个「随时可能发生的动作」变成了「有前置条件的动作」，因此**新增直调 `renderBrowsePage` 的入口必须先确认自己不可能在编辑会话期间发生**（当前三个：翻页、他人页首帧、导入后的他人页重绘 —— 最后一个已改走 `renderBrowsePageDeferred`）。
- 挂起与 IME 天然相容：挂起期间不碰 DOM，输入法组合不会被打断。
- `syncCardAfterStarChange` 里「有激活筛选 ⇒ `applyFilters`」与挂起门叠加后，星标变更的筛选重算最多推迟到编辑结束，不再打断用户。

## 残余风险

1. 编辑器挂着不动（用户把窗口丢在那儿）时挂起不会自愈，网格一直停在旧画面；下次任何失焦/按键即兑现。
2. Turbo 自己换掉整帧（用户点导航链接）时节点由 Turbo 删除，脚本收不到任何信号；草稿可能丢。用户点击会先失焦提交，键盘导航（如 Alt+←）例外。
3. 挂起基于「页面上有编辑器」这一 DOM 事实；若将来新增第五种卡片内联编辑控件，必须把它的类名加进 `src/inlineEdit.ts` 的选择器，否则它不受保护。
4. 判据覆盖不到分页器的页码输入框（有意排除：分页器节点被整体搬进分片、重绘后会原样带回）。
